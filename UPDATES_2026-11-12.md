# AEPMS Video — single-pass compression and mobile UI update

## What changed

- Removed the six-pass transcode loop. Clips are now planned from their duration and processed **once**.
- Output planning aims for **42.5 MB** under a strict decimal **50,000,000-byte** cap, reserving headroom for encoder/container variability.
- Dynamically chooses video bitrate, audio bitrate, frame rate, and a maximum encoder-safe resolution before work starts.
- An already compliant file is returned unchanged, avoiding unnecessary quality loss.
- Progress is broken into preparing, encoding, finalizing and completed stages. The UI shows percentage, estimated playback time left, output bytes, and a cancellable operation.
- Cancellation now aborts pending player/encoder waits; stalled video playback gets a finite error timeout instead of an endless spinner.
- Source metadata loading is time-limited, and multiple file selections cannot overwrite each other's metadata.
- Off-screen video playback initializes the recorder before starting playback, preserving the start of short clips.
- The mobile interface has smaller headers/metrics, expandable camera options and source preview, contextual help `?` buttons, and a more visible conversion progress card.
- Recorded originals remain available even if compression fails or is cancelled; no file is uploaded automatically.

## Important technical limitation

Browser `MediaRecorder` encoders can ignore requested bitrates, and no portable browser API can promise an exact 50 MB final file for arbitrary video lengths/codecs in one pass. If the final file exceeds the limit, the app rejects that result with a clear message rather than falsely reporting successful compression or truncating the original. Try 240p in Settings or use a desktop/native encoder for an exceptional clip. Similarly, formats such as MP4 are only produced when the browser supports that encoder. Conversion happens at approximately playback speed and needs a visible, awake browser tab.

## Test commands

```bat
npm install
npm test
npm run build
```

On Windows 11, you can use `pnpm install`, `pnpm test`, and `pnpm build` with the included lockfile instead.

Automated tests validate bitrate/resolution planning, size headroom, camera settings migration, and the existing live recording cutoff protections. Test a short camera take and at least one oversized file on the specific Android and iOS devices used in the field before publishing a production release.
